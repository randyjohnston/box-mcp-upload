# Simplification candidates for consideration

These are proposals, not removals made by this patch. The goal is a small developer harness for hosted MCP, CCG, authorization code, uploads and debugging. Preserve useful request evidence and correct credential handling.

| Candidate                                                                                           | Why consider removing or reducing it?                                                                                                                                                                                                                                                                     | What would be lost?                                                                                                                          |
| --------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------- |
| In-process MCP wrapper for every Platform operation (`src/mcp/client.ts`, `src/mcp/tools.ts`)       | Platform CCG and authorization-code behavior can be tested with direct function calls. Creating an SDK client/server pair for each HTTP request adds request dispatch, error translation, and timeout and notification handling that Box-hosted MCP does not require. This is the largest structural simplification candidate. | Reuse of the same tools by the web app and standalone MCP server. Actual hosted MCP transport must remain.                                   |
| Standalone stdio server and its live CCG runner (`src/mcp/server.ts`, `scripts/e2e.ts`)             | Optional if the intended product is only the browser workbench and Box-hosted MCP. The runner requires saving a temporary file on the computer running the server before calling a tool, and exercises a different MCP server from Box's.                                                                 | Testing external clients against this project's own MCP server. Keep if that is a use case.                                                  |
| Future Vercel deployment design (`docs/deployment.md`)                                              | Shared stores, workers, queues and distributed limits are outside a harness used on one developer’s computer. None are needed for the current task; the document can be shortened to a limitations note.                                                                                                  | A starting plan if hosted multi-user operation becomes a real requirement. Do not implement it speculatively.                                |
| Repeated explanatory UI copy (`src/components/AuthWorkbench.tsx`, `src/components/BoxUploader.tsx`) | Auth routing, upload order and server-byte rules appear in several places. Keep concise active configuration in the UI and move longer explanations to the README.                                                                                                                                        | Some inline onboarding. Keep credential identity, actual transport, status and error detail visible.                                         |
| Request-history persistence (`sessionStorage` in `BoxUploader.tsx`)                                 | Optional convenience beyond a simple current-run trace. Could be replaced with an explicit export if history is distracting.                                                                                                                                                                              | Trace continuity across OAuth redirects and reloads; that can be useful for authentication debugging, so this is a lower-priority candidate. |
| Remote-serving support and global capacity policies (`src/auth/session.ts`, `src/staging.ts`)       | If the scope is strictly loopback-only, the remote password gate and hosting-oriented global caps could be reconsidered together with remote support. Keep a file-size limit and cleanup to bound disk use on the computer running this app.                                                              | The ability to expose the harness beyond loopback. Do not remove protections while leaving remote credential access available.               |

The MCP binary server route reads the whole temporary file into memory (`src/mcp/tools.ts`). Keep that limitation visible when testing large files. Replacing it with streaming, or removing that route if it is not needed, is a separate decision; neither change is included here.

Keep OAuth state/PKCE, app-bound token refresh, upload-ticket validation, same-origin checks, staged-file ownership, byte integrity checks and uncertain-write handling. These directly affect whether the harness tests the intended flow and reports a trustworthy outcome.

Cross-account fallback remains available. The harness labels the actual destination instead of imposing an account-matching policy.
