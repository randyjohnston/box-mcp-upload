# Simplification candidates

These features remain in place. Consider removal only if the lost capability is not needed to test MCP, CCG, authorization code, or debug uploads.

| Candidate                                                                         | Why simplify it?                                                                                                                        | What removal would lose                                                                                                                 |
| --------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------- |
| MCP SDK wrapper per web request (`src/mcp/client.ts`, `src/mcp/tools.ts`)         | Platform calls could use ordinary functions. The extra client/server pair adds dispatch, error conversion, timeouts, and notifications. | Shared tools for the web app and standalone MCP server. Keep the actual Box-hosted MCP client.                                          |
| Standalone stdio server and CCG runner (`src/mcp/server.ts`, `scripts/e2e.ts`)    | A second MCP server and upload-ID workflow may be unnecessary for a browser harness.                                                    | Tests with external stdio clients.                                                                                                      |
| Future deployment plan (`docs/deployment.md`)                                     | Queues, shared stores, and workers are not implemented or required to run the harness.                                                  | Planning notes for a future hosted service.                                                                                             |
| Repeated UI explanations (`AuthWorkbench.tsx`, `BoxUploader.tsx`)                 | Auth order and upload policy appear several times and can drift from the code.                                                          | Inline help; retain account, destination, transport, status, and errors.                                                                |
| Request history in session storage (`BoxUploader.tsx`)                            | Optional persistence code. Low priority: it is useful during OAuth tests.                                                               | Trace continuity across redirects and reloads.                                                                                          |
| Remote CCG access and capacity policies (`src/auth/session.ts`, `src/staging.ts`) | Candidates only if the app becomes strictly loopback-only.                                                                              | Access from another computer. Keep access controls while remote access remains supported.                                               |
| Generated Archify viewer (`docs/diagrams/architecture.html`)                      | About 700 KB of generated viewer code dominates the diff. It is documentation, not app runtime code.                                    | Zoom, themes, and path tracing. Retained because an Archify diagram was requested; a static image would be enough for the README alone. |

The MCP binary server route reads the whole temporary file into memory. Streaming it would reduce memory use but add implementation work; that change needs approval. The limit is documented in [architecture.md](architecture.md#upload-routes).

Keep PKCE and OAuth state, credential-specific refresh, upload-URL validation, same-origin checks, temporary-file ownership, byte-integrity checks, and uncertain-write handling. These determine whether a test uses the intended credential and reports a reliable result. Cross-account fallback stays available and labels the actual destination.
